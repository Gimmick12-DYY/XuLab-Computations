# m33: audit of the peaks -> ABC elements -> genes -> Perturb-seq path (descriptive, tables only)

User (2026-11-16): something may be essentially wrong in the simple ABC path, since it says our raw data carry no information on gene regulation. Treated as a possible pipeline error.

Comparison used everywhere (no p values): per TF, a gene list from binding vs the Perturb-seq list. Perturb-seq = Arm 2 raw per-TF z, all cells (m15 "raw" ZA; halves Z1/Z2), own gene removed, 11,228-gene universe. Responding = |z| >= 2; reproducible = |z| >= 2 in both halves, same sign. Columns: n targets, n responding, n shared, expected (targets x responding / N), fold, top-200 hits (the 200 highest-scoring targets that respond) with the expected number (200 x responding / N), same for reproducible responders.

Part A, mechanical audit, each check reported pass/fail with the evidence row:
A1 genome build: chromosome names and coordinates of lab peaks within hg38 lengths (ABC chrom sizes); fraction of top-5,000 summits inside canonical ABC candidate elements (ATAC-derived) vs the same summits shifted 1 Mb (a wrong build behaves like the shifted set); NRF1 summits within 500 bp of the TSS of known NRF1 targets (TFAM, TFB2M, POLRMT, CYCS, COX6C, ATP5F1B, NRF1-independent control: none); m22_build.py code inspected for any hg19 source (pmat).
A2 peak file identity and columns: file path per TF; summit (start + col 10) inside [start, end) for every row; signalValue = col 7; top 5,000 ranked on col 7; own-motif evidence from m25 for TFs with a motif (identity check possible only there).
A3 joins: chromosome naming match peaks vs elements; summit-in-element convention (half-open, start <= summit < end); fraction of ABC links whose TargetGene is in the universe; universe genes with no link; duplicated symbols in GeneList / Perturb-seq gene list; self-promoter rows present.
A4 Perturb-seq rows: on-target logFC per TF from the m4 guide_qc (negative = knockdown seen); z of the TF's own gene before removal (negative = row belongs to that TF and sign convention z = KD - NTC).
A5 hand trace of 5 edges (NRF1, E4F1, CTCF, NFYA, HOXB6 as a shallow TF): the strongest supported edge per TF: raw narrowPeak line, element, ABC link row, gene, z.
Part B, positive control for the path: bulk ChIP peaks through the identical code (top 5,000 by col 7, summit = start + col 10, strongest summit per element, signal x ABC over canonical links, same universe): CTCF HEK293T (GSE103651), CTCF HEK293 (ENCODE), MAZ HEK293, ZIC2 HEK293, ZNF282 HEK293, ZNF777 HEK293, ZBTB7A HEK293, SETDB1 HEK293, NFYA K562, and public ENCODE downloads (by accession only): NRF1 K562 ENCFF259YUE, NRF1 HepG2 ENCFF348EDE, E4F1 K562 ENCFF683WRK. data/CTCF_293Tcon1_pval_peaks.bed has no signal column and is not used. Side by side with our HITAG list for the same TF.
Part C, simpler variants of our data, all 75 TFs: (0) current m22 (top 5,000, ABC); (i) promoter-only: top-5,000 summits within +-1 kb of the TSS, no ABC; (ii) top 500, 1,000, 2,000 peaks with ABC; (iii) nearest TSS: each top-5,000 summit to the nearest universe TSS; (iv) raw 5'-end fragment counts in TSS +-1 kb (m10 w1k counts), top 1,000 genes per TF, no peak calling; (v) (iv) divided by ATAC reads in the same window (ABC Genes.TSS1kb ATAC counts), genes with >= 20 ATAC reads, top 1,000. Summary per variant: median fold over TFs and the values for NRF1, E4F1, CTCF, NFYA, MAZ, DNMT1.
Any bug found is fixed and the affected outputs rerun, with what changed stated.
